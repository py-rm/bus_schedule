# Дачные (садоводческие) автобусы Оренбурга — парсер расписаний

Парсер скачивает расписание дачных автобусов с официального портала города
Оренбурга и сохраняет его в один JSON-файл.

## Источник данных
- Главная страница со списком маршрутов: https://orenburg.ru/activity/16226/
- Каждый номер — ссылка на свою страницу с расписанием.

## Файлы проекта
| Файл | Что это |
|------|---------|
| `orenburg_dacha_parser.py` | Парсер расписаний (Python) |
| `dacha_schedule.json` | Результат — файл с расписаниями (создаётся при запуске) |
| `dacha_news_parser.py` | Парсер последней новости об изменениях маршрутов (Python) |
| `dacha_news.json` | Результат — файл с последней новостью (создаётся при запуске) |
| `schedule_viewer.py` | Настольный просмотрщик JSON (tkinter), собирается в `.exe` |
| `schema_check.py` | Проверка качества JSON после пересбора (MD5, времена, структура) |
| `README.md` | Эта инструкция |

> Остальные `.py`-файлы и `test.html` в папке — старые черновики, можно не трогать.

## Как запустить (расписания)
Открой командную строку в папке проекта и выполни:
```
cd D:\Python
python orenburg_dacha_parser.py
```
После запуска в той же папке появится (перезапишется) файл `dacha_schedule.json`.

Пример вывода в консоли:
```
Шаг 1: собираем список маршрутов с главной страницы...
  Найдено маршрутов: 41
  ...
[41/41] Маршрут №94 ...
Готово. Маршрутов: 41
Общий MD5 файла: ...
Файл сохранён: dacha_schedule.json
```

## Как запустить (последняя новость о маршрутах)
Скрипт читает RSS-ленту новостей портала, отфильтрованную по сфере
«садоводческие маршруты» (activity=16226), и берёт из неё **самую свежую**
(первую) новость — например, об изменении расписания, графика работы или
рабочих/выходных дней.

```
cd D:\Python
python dacha_news_parser.py
```

Как работает:
- RSS возвращает новости от свежих к старым, поэтому первая новость в ленте —
  последняя актуальная.
- Скрипт запоминает новость по её `news_id` (число из ссылки вида
  `.../presscenter/news/321572/`) и MD5.
- Если новостей не появилось — файл `dacha_news.json` не меняется.
- Если появилась новая новость — файл перезаписывается.

## Как открыть результат (JSON)
`dacha_schedule.json` — обычный текст:
- просто перетащи файл в окно браузера — он красиво развернётся,
- или открой через **VS Code**: `code dacha_schedule.json`,
- или Блокнотом.

Листать файл колёсиком мыши. Поиск по слову — `Ctrl+F`.

## Настольный просмотрщик (Windows .exe)

Программа для просмотра расписания на компьютере без чтения JSON вручную.
Читает `dacha_schedule.json` и `dacha_news.json` из своей папки.

Запуск из исходника:
```
python schedule_viewer.py
```

Сборка .exe (PyInstaller):
```
python -m PyInstaller --onefile --windowed --name DachaScheduleViewer --noconfirm schedule_viewer.py
```

После сборки положить рядом с `DachaScheduleViewer.exe` файлы
`dacha_schedule.json` и `dacha_news.json`.

Возможности:
- сетка номеров маршрутов (7 в ряд) + поиск по номеру/названию;
- клик по номеру — окно маршрута: дни работы, перевозчик, блоки расписания,
  MD5 маршрута;
- внизу главного окна — карточка последней новости из `dacha_news.json`;
  клик по ней открывает полную новость со ссылкой на источник.

## Проверка данных (schema_check.py)

Разовый запуск после каждого пересбора JSON, чтобы ошибки не ушли дальше:
```
python schema_check.py
```
Проверяет `dacha_schedule.json` и `dacha_news.json` из своей папки
(пути можно задать через `--schedule` / `--news`):

- `routes_count` совпадает с числом маршрутов; номера уникальны;
- у маршрута непустые поля `number`/`name`/`url`;
- MD5 маршрутов и общий MD5 каждого файла совпадают с пересчитанными;
- нет блоков без остановок; `valid_from` в формате `ДД.ММ.ГГГГ`;
- времена строго `HH:MM`, в пределах 00:00–23:59, без повторов,
  по возрастанию (порядок — предупреждение);
- у новости непустые `news_id`/`title`/`url`/`date`/`text`.

В конце печатает «ОШИБОК: N / ЗАМЕЧАНИЙ: M».

### Код возврата (важно для облака)
Скрипт завершается с одним из трёх кодов — это «шлюз» перед публикацией:

| Код | Значение | Когда | Действие в облаке |
|-----|----------|-------|-------------------|
| `0` | OK | всё чисто | публиковать смело |
| `2` | WARN (мягкая тревога) | есть замечания (напр. маршрутов стало меньше на 1–3) | публиковать, но уведомить администратора |
| `1` | ERROR (жёсткая тревога) | есть ошибки (повреждён JSON, маршрутов стало меньше >3 и т.п.) | **НЕ публиковать** (оставить прежний файл), уведомить администратора |

### Порог по количеству маршрутов (`--expected`)
Чтобы поймать случай «сайт сломался / вёрстка поменялась, маршрутов резко стало
меньше», передай ожидаемое число маршрутов:
```
python schema_check.py --expected 41
```
- маршрутов стало меньше на **1–3** → код `2` (WARN, продолжаем, но уведомляем);
- маршрутов стало меньше **более чем на 3** → код `1` (ERROR, стоп, уведомляем).

Без `--expected` это сравнение не выполняется (работает только проверка структуры).

В облаке число-эталон (`41`) хранится в настройке Cloud Function и передаётся
скрипту — с чем именно сравнивать, смотри в `DEPLOY.md`.

## Структура JSON
```
{
  "generated_at": "дата создания",
  "source": "ссылка на источник",
  "global_days_off": "понедельник, четверг",
  "routes_count": 41,
  "md5": "общий MD5 всего файла",
  "routes": [
    {
      "number": "24С",
      "name": "Маршрут №24С «Челюскинцев – г. Сулак (сады)»",
      "url": "ссылка на страницу маршрута",
      "carrier": "перевозчик и телефон",
      "days_notes": ["по вторникам, четвергам, ..."],
      "schedule": [
        {
          "days": null,            // ограничение по дням или null
          "valid_from": null,      // дата вступления в силу или null
          "note": null,            // пометка-подзаголовок блока или null
          "stops": [
            { "point": "Челюскинцев",     "times": ["08:00", "11:00", ...] },
            { "point": "Конечная (сады)", "times": ["08:40", "11:40", ...] }
          ]
        }
      ],
      "md5": "MD5 данных этого маршрута"
    }
  ]
}
```

Пояснение полей:
- `schedule` — список блоков расписания. Один блок = одно расписание для
  определённых дней и периода.
- `days` — на какие дни действует блок («Будни», «Выходные», «по вторникам...»)
  или `null`, если ограничений нет.
- `valid_from` — с какой даты действует этот график (например `01.09.2026`)
  или `null`. Если у маршрута несколько блоков с разными датами — это график,
  который сменит предыдущий.
- `note` — пометка-подзаголовок блока (например «в том числе рейсы ... до
  с/о Гребени:») или `null`. Пометка всегда стоит перед своими рейсами:
  она выносится в отдельный блок, а не относится ко всему предыдущему
  расписанию.
- `stops` — направления движения: `point` (название пункта) и `times`
  (время отправления). Время всегда приводится к единому формату `HH:MM`
  (например `8.00` на сайте станет `08:00`), так как на сайте пишут вручную
  и используют разные разделители (`.` или `:`).

Поле `generated_at` — дата/время создания файла в облаке (`YYYY-MM-DDTHH:MM:SS`).
Используется приложением для проверки актуальности и как защита от «отката»
даты на устройстве (анти-обман при принудительном обновлении — детали в
`NOTES.md`).

## Структура dacha_news.json
```
{
  "generated_at": "дата создания",
  "feed_url": "ссылка на RSS-ленту",
  "news": {
    "news_id": "321572",              // уникальный номер новости из ссылки
    "title": "Вниманию оренбуржцев!",
    "url": "https://orenburg.ru/presscenter/news/321572/",
    "date": "Вт, 12 мая 2026 08:21:00 +0500",
    "text": "текст новости",
    "md5": "MD5 данных новости"
  },
  "md5": "общий MD5 всего файла"
}
```

Приложение может показывать `dacha_news.json` как предупреждение об изменениях.
Если `news.md5` (или `news_id`) совпадает с той, что уже показана — новостей
нет. Если изменился — это новая/изменённая новость, которую стоит показать.

## Что такое MD5
MD5 — это «отпечаток пальца» данных (контрольная сумма).
- **MD5 маршрута** считается по данным этого маршрута. Если расписание
  изменится — отпечаток изменится.
- **Общий MD5** считается по всему файлу. Позволяет проверить, обновились ли
  данные (например, приложению — понять, что расписание новое).

MD5 при пересчёте подтверждается (проверено): общий MD5 в файле совпадает
с тем, что получается заново из содержимого JSON.

## Когда перезапускать
Дачные маршруты работают сезонно. Перезапуск парсеров актуален в периоды
изменения расписания:
- весна: середина апреля – середина июня (запуск сезона, летний график);
- осень: середина августа – конец октября (осенний график, завершение сезона).

Зимой маршруты не ходят, обновления не требуются. Парсер запускается вручную;
автозапуск по расписанию в облаке описан в `DEPLOY.md`.
